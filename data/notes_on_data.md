# Data Notes: CDC PLACES County Data

## Source
- Dataset: PLACES: Local Data for Better Health, County Data, 2025 release
- API: https://data.cdc.gov/resource/swc5-untb.json
- Format: long/tidy — one row per county + measure + value type (pivoted to
  wide during cleaning; see below)

## Cleaning steps applied

1. **Dropped Socrata artifact columns** — `:@computed_region_hjsp_umg2` and
   `:@computed_region_skr5_azej`, auto-generated by Socrata, not part of the
   real PLACES dataset.
2. **Removed national rollup rows** — 80 rows with `stateabbr == 'US'` and
   `locationid == 59` (a placeholder, not a real FIPS code). These are national
   summary rows mixed into the county file, not counties themselves. Some carry
   a footnote noting the estimate is "based on 39 states and DC" rather than
   all 50 — worth citing if referencing any national figure.
3. **Trimmed whitespace** on all text columns (state, county, category, measure
   names) to prevent silent filter mismatches.
4. **`locationid` (FIPS) kept as a zero-padded 5-character string** — casting to
   int silently drops leading zeros (e.g. "01001" becomes 1001), which breaks
   any join against a county boundary/GeoJSON file for mapping.
5. **`geolocation` parsed into numeric `latitude`/`longitude`** — the API
   returns this as a dict-string (`"{'type': 'Point', 'coordinates': [lon,
   lat]}"`), not the plain `POINT (lon lat)` text shown in the website's CSV
   preview. Parsed with `ast.literal_eval`, falling back to a regex match for
   the text format as a safety net.
6. **Pivoted crude vs. age-adjusted prevalence into two columns**
   (`crude_prevalence`, `adj_prevalence`) instead of two separate rows per
   measure — decided for easier dashboard filtering (no need to filter on
   `data_value_type` in every callback). County/measure descriptive columns
   (state, population, lat/long, category) were merged back in separately
   rather than included in the pivot key, since pivoting on 14 near-unique
   columns caused a "product space too large" crash — the fix was to pivot on
   only `locationid`, `measure`, and `year`, then join the descriptive columns
   back afterward.
7. **Confirmed safe to pivot**: checked for exact duplicate rows (0), rows
   sharing the same county+measure+value-type key (0), and county+measure
   combos where crude/adjusted disagreed on year (0) before pivoting.

## Known data limitations (kept, not fixed)

### Suppressed estimate: Loving County, TX (FIPS 48301)
33 rows have `NaN` for both `crude_prevalence` and `adj_prevalence` — the least
populous U.S. county, suppressed by CDC for sample size ("Estimates suppressed
for population less than 50"). **Team decision: kept as `NaN`** rather than
dropping the county, since it's a real methodological limit, not a data error.
Any chart/map using this dataset will show a gap for this one county on
affected measures — that's expected, not a bug.

### Mixed BRFSS survey years within one release
The 2025 release uses 2023 BRFSS data for most measures but 2022 data for 5
measures collected only every other year (all teeth lost, dental visits,
mammograms, colorectal cancer screening, short sleep duration). This means
`year` is not a single consistent value across the whole dataset — it varies
by measure, confirmed by checking for year mismatches within each
county+measure pair (found: 0, meaning crude/adjusted always agree on year for
the same measure, but different measures can still show different years).

### Crude vs. age-adjusted prevalence
Each measure carries two values: crude (raw observed rate) and age-adjusted
(re-weighted to a standard age distribution). Charting them against each other
is useful — counties where crude is much higher than adjusted are driven by an
older population, not necessarily worse health outcomes or access; counties
where adjusted is much higher than crude have a genuinely elevated rate despite
not skewing old, which is the more actionable finding for targeting resources.
